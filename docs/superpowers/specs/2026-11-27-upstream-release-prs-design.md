# Upstream release PRs via Renovate — design

## Why
New upstream releases go unnoticed for a while. A PR assigned to a human reviewer is the alarm; doing the bump in the PR is a bonus.

## Scope
- In: `charts/cloudbeaver` (docker.io `dbeaver/cloudbeaver`), `charts/pinniped-concierge` (ghcr.io `vmware/pinniped/pinniped-server`).
- Out (for now): `kubebrowser`, `wazuh-agent` (self-built images, need an issue-style alert on the real upstream), `raw` (no upstream).
- Non-goals: automerge, GitHub Actions / pre-commit hook updates, digest pinning campaigns.
- Anti-goal: PR noise on charts nobody asked about, or PRs merged without a human.

## Approaches
- **A. Renovate bump PRs (picked).** Detects + does the 4-file bump; reviewer approves.
- B. Cron Action opening issues only. Detects, but the bump stays manual; we own a script.
- C. Renovate Dependency Dashboard only. One long-lived issue — easy to ignore, same problem as today.

Where Renovate runs: a scheduled GitHub Actions workflow in this repo (`renovatebot/github-action`), authenticated by an org-owned GitHub App. Considered and dropped: a second `platform: github` release of the company Renovate (GitLab-only today, read-only GitHub PAT, needs helmfile/SOPS/Argo changes) and Mend's hosted app. `GITHUB_TOKEN` is not used because PRs it opens don't trigger CI.

## Design

### `renovate.json` (standalone)
- `enabledManagers: ["helm-values", "custom.regex"]`, `includePaths` limited to the two charts; one group (= one PR) per chart.
- `helm-values` updates `image.tag` (and pinniped's `image.digest`); `bumpVersion: "patch"` bumps `Chart.yaml` `version` (matches history: 1.1.7 → 1.1.8 per app bump).
- Regex managers: `Chart.yaml` `appVersion` (keeps `scripts/checkAppVersion.sh` green); pinniped only: the `## @param image.tag [default: …]` annotation and the `icon:` URL tag.
- README table and `values.schema.json` are regenerated by a `postUpgradeTasks` run of `readme-generator-for-helm@2.7.0` — the same tool the pre-commit CI job checks, so table padding and digests stay exact.
- `reviewers: ["Brawdunoir"]`, `labels: ["upstream-release"]`, no automerge, Dependency Dashboard on (from `config:recommended`).
- Pinniped PRs carry a `prBodyNotes` reminder to diff/re-sync `crds/` and `templates/rbac.yaml` (copied from upstream install YAML; the `(v0.48.0)` comment in rbac.yaml is deliberately left for the human).

### `.github/workflows/renovate.yml`
- Daily cron + `workflow_dispatch`; `actions/create-github-app-token` mints the token from `vars.RENOVATE_APP_ID` / `secrets.RENOVATE_APP_PRIVATE_KEY`.
- Env: `RENOVATE_REPOSITORIES` = this repo, onboarding off, config required, platform commits (signed by the App), `RENOVATE_ALLOWED_COMMANDS` restricted to the readme-generator command.

## Manual steps (humans)
Org admin creates the GitHub App (Contents, Pull requests, Issues: read/write; Metadata: read; no webhook), installs it on `AvistoTelecom/charts` only, and stores its ID as repo variable `RENOVATE_APP_ID` and private key as repo secret `RENOVATE_APP_PRIVATE_KEY`.
